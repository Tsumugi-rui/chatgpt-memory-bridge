# ChatGPT Memory Bridge v0.10.11

读取旧账号 → 存入资料库 → 勾选对话 → 分别导入新账号的多个聊天。

## 日常操作

1. “读取旧账号”连接浏览器插件 1.4.1，选对话采集，传送完成后自动入库。
2. 已有备份只需“扫描备份文件夹”，选最外层目录。软件递归查找嵌套 ZIP，归并同对话旧包和分卷。切到“待入库备份”勾选整条记录，读取所选入库；无需逐卷选文件，缺卷会提示。
3. 在“已保存的对话”勾选需要接续的记录，点击“本地分对话接续”。
4. 点击“打开项目资料目录”，在新账号桌面 Work 建一个“旧账号对话”本地项目，关联总目录。
5. 在同一个项目里为每条旧对话分别新建聊天。从软件列表选中对应对话，点“复制这条对话的接续指令”并发送。指令会定位到自己的子目录。

网页辅助可使用“网页 Work 批量导入…”。提前在浏览器登录目标新账号，确认后插件逐条打开空白聊天，各自上传正文和附件、发送独立提示词。每批最多五个文件。网页额度、格式或页面变化可能导致暂停，结果写入“导入结果.json”。

“生成上传资料”可以单独使用。多选时每条对话位于独立子文件夹，各自带有提示词。同一条对话的多段续聊共同使用一个接续编号。已有导出文件保留在原位置。

目录仅包含所选对话，保留历史版本及元数据，匹配所选附件；正文默认每片不超过 128 KiB，长消息也保留。原始 ZIP 留在主资料库，不重复打包整库。

导入通过已登录浏览器的上传控件和发送按钮执行，新账号会收到含历史资料的新聊天。账号登录由用户完成。网页上传额度、格式支持和页面布局会影响执行。

## 网页辅助

插件一键导入会分批上传当前选择的资料。超出账号额度或遇到不支持的文件时会暂停，请核对网页提示。大资料也可使用桌面 Work 的本地文件访问方式。

## 安装与数据

运行交付目录中的“打开迁移软件.lnk”或“软件/MemoryBridge.exe”，保留 _internal，无需另装 Python。开发版运行 `.venv/Scripts/python -m memory_bridge gui`。

插件需更新到 1.4.1，并在浏览器扩展管理页重新加载。打开软件后默认自动连接；只有识别失败时才用备用配对码。更新插件应保留安装路径和扩展数据，避免丢失断点。

ZIP 保留对话名、导出时间及时区、对话 ID，超过 120 MiB 自动分卷；读取时校验并原样重组，同一对话只建一条记录。支持旧插件包和官方 ZIP。原始 ZIP、未知字段、分支和版本是权威资料，结构化记忆只是可重建的派生数据。

扫描卷数齐全不等于内容已经验证，入库时还会校验。插件只采集显示分支；列表可能遗漏归档或未展开项目。附件未取得会报告，单附件仍有 25 MiB 限制。

“存储设置…”只需选一个“数据保存位置”，软件自动建立：资料库/、浏览器备份/、接续目录/、完整备份/。旧配置仍可读取，保存统一位置后生效；勾选复制可整理现有资料库，原件保留，新“资料库”子目录须为空。已有输出文件不自动搬动；打开已有统一目录时取消勾选复制。

软件自动采集中途暂停时，只要未取消任务且有片段，就尝试生成部分 ZIP 并入库；提示“部分备份已入库，可继续采集”。没有成功导出的旧断点会与后续片段一起完整导出。只有全部分卷传送完成且软件确认收到完成通知后，才更新增量基线；传送或通知失败不会跳过旧片段。1.3.0 的旧送达标记需重新完整导出一次，避免误把未完成备份当成已送达。

升级请保留已安装插件的原目录和浏览器数据，只在扩展管理页重新加载，再刷新 ChatGPT 对话。不要移除插件或清空断点。软件 v0.8.1 随附 1.3.1；用旧软件也须更新实际正在使用的插件。

## 跨账号续聊

1. 在“已保存的对话”只勾选一条要继续的对话，点击“生成上传资料”。网页和桌面提示词都含有该对话的接续编号。
2. 在新账号发送提示词时保留编号所在行。以后采集该对话并入库，软件从用户消息中识别编号，将续聊接到原对话后面。
3. 对已经存在的记录，右键新账号对话，选“归入已有对话…”，选择原对话并确认。列表会优先显示同名候选。
4. 右键“查看或拆分续聊…”可以查看各段的账号标识和消息数量，也可以移出某段。勾选这条对话生成资料会包含各段正文、来源和顺序。完整资料库备份也会保存归类关系。

自动归类需要可识别的接续编号。合包时各段保留原账号标识、对话 ID 和原始 ZIP。只选择一条对话生成资料，才能为目标对话生成唯一接续编号。

新生成的正文分片使用「记录序号 标题 - 分片序号.md」命名，例如 `002 助词练习 - 分片0001.md`。记录序号按资料包中的导出顺序排列，分片序号从每段记录重新计数。标题包含文件名限制的字符时会替换，完整原标题见 `对话目录.json`。

## 永久删除对话

在“已保存的对话”中右键一行，选择“永久删除对话…”并确认。资料库会清除对话正文、版本、搜索索引、仅源于这些消息的记忆，以及对应的原始 ZIP 和分卷。续聊分组会整组删除，只删其中一段时请先拆分。若有多条对话共用原始 ZIP，请勾选全部相关对话，再右键选择“永久删除勾选项…”。

之前移入“回收站”的对话也可以右键永久删除。之前生成的独立备份和接续资料仍可在原位置找到。

## 重采与续采核对

软件配合插件 1.3.2，会核对上次送达的原始 ZIP、校验值及采集范围。永久删除、归档缺失或损坏后，下次采集会从当前对话开头开始。移入回收站的对话也会从头重采，首尾检查通过并入库后回到“已保存的对话”。重采中断后可以继续新断点。

也可勾选对话并点“从头重新采集…”。旧 ZIP 保留为历史备份。普通采集仍可沿有效断点继续，每次软件接收的新版 ZIP 都包含本轮保留的正文片段。插件更新后请在浏览器扩展管理页重新加载并刷新对话网页。

采集结果不完整、网页读取出错或 ZIP 未送达时，本轮会暂停后续对话。已送达的部分备份仍可入库，可单独勾选当前对话继续。旧断点没有核对过开头时，采集会从开头补齐。

## 清空本地存档

在“工具 → 备份与恢复”选择“清空本地存档…”。确认后，当前资料库、当前输出位置的浏览器备份、接续目录和完整备份会被永久清空。独立存放在其他位置的 ZIP 仍可从原位置找到。插件连接到软件后会清除断点。

软件升级首次启动时清理当前资料库临时文件和浏览器备份目录中的未完成传输文件。插件升级首次运行时清理旧采集断点和连接缓存。

首次采集、从头重采及缺少开头的断点会直接定位到对话开头，再向下采集并核对末尾。已核对开头的有效断点可以继续增量采集。

一个本地项目可以关联总资料目录，各聊天通过独立提示词定位子目录。跨设备继续需要账号支持 Work Cloud 与本地电脑访问，并在启用后新建云端任务。读取本地文件时存放资料的电脑需在线。项目关联目录不会自动上传整个目录。官方说明见 https://learn.chatgpt.com/docs/get-started-with-work#continue-work-across-devices 。

本批网页导入统一使用 Work。插件先选择 Work 并核对选中状态，再读取并上传所选对话文件。页面缺少 Work 或状态无法确认时，本条暂停并停止后续队列。每条对话的模式记录为 work，已有导出文件继续保留。网页控件识别通过合成页面测试，首次使用请确认页面实际状态。

网页 Work 切换同时识别英文 Work 与中文“工作”。网页中文按钮标签及可见文本输入框也可识别。

新 Work 页面会等待上传输入控件，必要时展开上传菜单。采集完成后，待 ZIP 送达并保存断点，再在同一处理标签页切换到下一条链接。导入成功后也复用这一页进入新聊天，已有云端聊天继续保留。失败时停在当前页。

“中断上传”停止当前网页导入和后续导入队列，保留已发送聊天、本地资料及进度报告。程序在上传文件、发送消息前核对取消状态，插件轮询时结束待上传页面。正在提交的一批需对照网页核对。每批等待回复后再继续，全部文件发送后另发独立结束指令。

网页导入收尾后，插件通过当前聊天的重命名菜单设置原对话名，并核对侧边栏保存结果。改名无法确认时写入导入结果，已上传资料继续保留。

导入进度逐批保存。点击“继续未完成上传…”选择原导入结果，可沿原聊天跳过已确认发送的文件，只补传剩余资料或收尾指令。收尾指令送达后，模型回复未出现不会抹去上传结果。发送本身未确认时需先人工核对。

发送确认改为核对当前消息的唯一迁移校验码，适配页面移除较早消息的情况。续传时可重新核对待确认消息的校验码；未找到时暂停。
