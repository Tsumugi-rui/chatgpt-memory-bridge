# ChatGPT Memory Bridge 浏览器插件 v1.3.0

## 从旧版更新，保留断点

配合软件 v0.7.0：在软件点击“连接插件”，将 6 位配对码填入插件图标弹窗连接；然后在软件读取对话列表、选择对话并开始导出。插件按队列打开采集页，使用本机 127.0.0.1:18765 传送 ZIP，不上传云端。软件关闭后需重新配对。超过 120 MiB 的导出会分卷，软件导入时一起选择，重组成同一份对话备份。列表来自网页可加载的侧边栏，不使用内部接口，不保证列出归档或未展开项目内的对话。

软件“插件安装与说明…”可备份并更新原安装目录；更新后仍需在扩展管理页重新加载，并刷新 GPT 网页。

保持原插件安装目录不变，更新该目录内的程序文件，然后在 edge://extensions 点击该插件的“重新加载”。不要“移除”插件，不要清除扩展数据，也不要换一个目录重新安装。

回到 GPT 网页刷新一次，再点插件图标打开面板。新面板标题带“1.2”，会自动无损迁移旧断点；等迁移完成后点继续。之前已导出的 ZIP 请保留。

1.1 取消了旧的 120 MiB 重复页面累计阈值。相同原文只存一份，各片段保存引用，再用 gzip 压缩本地断点。不同原文版本仍会保留。导出不清空数据；继续时从最后保存位置前一个视口恢复，遇到缺口再慢速核对全文。设备内存、磁盘和浏览器存储仍是实际限制。

这是独立的 Edge / Chrome 插件。使用时不需要 Python、Node.js、模型 API 或官方导出 ZIP。

## 安装到 Edge

1. 在 Edge 地址栏输入 `edge://extensions`。
2. 打开左侧的“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择本交付包中的 **extension** 文件夹，也就是直接包含 `manifest.json` 的那一层。
4. 在浏览器扩展菜单中找到“ChatGPT Memory Bridge · 对话备份”，可将它固定到工具栏。

Chrome 安装入口是 `chrome://extensions`，其余步骤相同。ZIP 需要先解压，不能直接选择 ZIP 文件。

这是本地加载的插件，未上传扩展商店；当前尚未在用户的 Edge 中安装或完成实测。已经过自动化测试，详见交付目录的验证报告。

## 保存一条对话

1. 登录 ChatGPT，在网页打开一条具体对话，例如“日语学习”。
2. 点击插件图标，再点击“打开备份面板”。
3. 在网页右下角点击“开始完整采集”。首次采集自动向前加载历史，再从开头向后滚动；暂停后继续会从断点前一小段恢复并检查衔接。
4. 等面板显示采集结束，核对首尾和消息数，点击“导出 ZIP”。下载位置由浏览器设置决定。

请保持页面打开，采集时不要手动切换分支或对话、刷新、编辑消息或发送新消息。无需一直打开插件弹出窗口。关闭右下角面板只隐藏面板，任务继续；再次点击插件图标可以找回面板。

网页加载慢时可选“慢速”。持续加载更早内容超过 90 秒会暂停，保留断点；网页恢复后点继续。程序发现片段未衔接，会自动再慢速补读一次；仍有缺口时保留分段，不伪造完整状态。

暂停后可导出当前资料。断点保存在本浏览器、本用户配置的扩展本地存储中；刷新网页后，重新点击插件图标可以恢复断点并再次核对全文。浏览器清理扩展数据或卸载插件会影响断点，因此应及时导出 ZIP。插件不提供自动清空按钮。

## ZIP 包里有什么

- `打开阅读.html`：解压后双击阅读，已保存的图片可离线显示。
- `对话全文.md`：可上传到新账号的文字和引用。
- `对话全文.json`：包含消息、来源、未衔接片段及同一消息的内容版本。
- `原始片段.json`：引用式原始档案。`dictionary` 保存每份不同的原始消息，`job.snapshots[*].messages` 保存字典下标。按下标可还原每次采集的 HTML、正文、附件引用、顺序和时间位置。程序中的 `BridgeStore.unpack` 可还原为旧格式，不会因为去重丢掉版本。
- `assets/`：成功下载的图片和附件。
- `附件清单.json`：每个附件的原始引用、下载状态、失败原因及校验值。
- `完整性报告.json`：页面开头、末尾、片段衔接、首尾正文和缺口情况。
- `manifest.json`：包内其他文件的字节数及 SHA-256，清单不包含自己。
- `新账号接续提示词.txt`：上传全文后可复制发送。

导出会保留原始片段。生成摘要不会取代原消息。它不会自动上传资料到新账号，也不能恢复 ChatGPT 官方侧边栏或记忆状态。

## 图片和附件的实际范围

插件读取消息中实际出现的图片与文件链接，不探测内部接口。会尝试读取 ChatGPT、oaiusercontent.com、oaistatic.com 的 HTTPS 资源，以及当前页面仍有效的 blob/data 图片。

过期文件、网站拒绝访问的文件、没有直接链接的“下载附件”按钮、外部网站资源或超出容量的文件会在清单中标记，不声称已下载。没有直接链接的附件需要你在原对话里手动点击下载，并与迁移包一起保存。

单个附件上限仍为 25 MiB，导出附件合计仍为 150 MiB。正文不再按重复页面累计到 120 MiB 就停止。本地断点经过引用去重和 gzip 压缩；ZIP 内的原始档案也使用引用式格式。导出 ZIP 会占用额外内存，设备资源不足时会报错并保留断点；不能承诺无限容量。此版本不支持批量遍历整个账号、不支持自动切换所有分支。

## 完整性含义

“页面边界与片段衔接检查通过”表示：程序到过当前页面的顶部和底部，取得的片段可以连接。它不是对账号全部历史、所有分支、所有附件的保证。网页若本身缺数据，程序不能重建不存在的内容。

重复短句不会仅按全文相同就直接删除。优先使用消息 ID，其次使用相邻片段的连续重叠；无法确定时保留为单独片段，并报告缺口。连续多条用户发言会全部保留，不强行整理成一问一答。

网页结构将来可能改变。识别不到消息时会提示等待或停止，应更新适配器后再试。

## 开发与测试

`collector.js`：页面适配、自动滚动、断点和导出；`core.js`：消息拼接；`zip.js`：零运行依赖 ZIP；`background.js`：下载实际观察到的资源；`popup.js`：手动打开面板。

开发机安装依赖后运行 `node --test tests/*.test.cjs`。依赖仅用于合成 DOM 测试，不随安装版分发。测试和发布包不包含真实聊天记录。

权限用途：`activeTab`/`scripting` 用于点击插件后注入采集器，`storage`/`unlimitedStorage` 用于本地断点，指定网站权限用于当前页面和附件下载。不读取或导出密码、Cookie、令牌，不调用模型，不上传聊天正文。

## 导出文件名

从 1.2.1 起，自动和手动导出的 ZIP 都按“ChatGPT__对话名__本地导出日期及时间_UTC时区__对话ID.zip”命名。中文、日文标题保留，Windows 不支持的符号替换为下划线，过长标题截短。分卷沿用同一名称，再附加 part-0001-of-N；日期表示导出时间，不是原始对话创建时间。历史导出文件不会被自动重命名。

## 1.3 增量与直连

软件 v0.7.0 改用黑白横向菜单布局。插件 1.3.0 启用后默认尝试直连本机软件，无需配对码；仅允许本机浏览器登记的 Memory Bridge 扩展，识别失败时可从软件“更多”复制备用配对码。顶部显示连接与采集状态。

同一对话保留压缩断点，先定位上次尾部并验证重叠，再读取新增片段，不主动重读开头。衔接失败保留两段并提示。软件调度的已成功传送备份后续只导出增量与重叠证据，旧数据留在资料库，按同账号及对话 ID 合并；增量包不能单独代表完整历史，首次旧备份也必须入库。网页手动导出仍包含当前本地保存的全部片段。不要卸载插件、清空断点或换安装目录。


## 1.3.1 中断恢复

区分已采集游标与软件确认送达的快照基线。未导出的断点下一次全部打包；旧版无回执的基线重新完整导出一次。继续前探查最新片段，延长末尾稳定等待并核对已见最新消息。自动采集中途暂停时尝试导出带缺口报告的部分包，入库后可继续；取消任务或传送失败仍保留浏览器断点。原路径更新、重新加载扩展并刷新网页后生效，不要卸载或清空存储。

## 1.3.2 重采与归档核对

新增“从头重新采集”，为选中的网页对话重建断点。与软件 v0.9.3 连接时，先核对已送达的归档，再决定续采位置。软件接收的 ZIP 包含全部保留的正文片段。

## 1.3.3 长对话采集

自动定位正文滚动容器，短暂卸载正文时等待恢复。旧断点未核对开头时重新寻找开头。搭配桌面端 0.9.6，部分或失败的采集会暂停后续对话。

## 1.3.4 升级缓存清理

升级后首次运行会清除旧采集断点和连接缓存。收到桌面端清空存档通知后，插件也会清除采集断点。已打开的采集页面需刷新后继续使用。

## 1.3.5 采集顺序

从头采集或断点没有核对过开头时，直接回到开头，再向下采集并核对末尾。

## 1.3.6 片段衔接

同一对稳定消息 ID 之间的无 ID 空白用户占位可与已采集的实际内容衔接，优先保留带正文或附件的记录。

## 1.3.7 图片消息识别

读取气泡内部唯一的消息 ID，在图片加载时仍能关联同一条消息。支持从 images.openai.com 下载网页已显示的图片。

## 1.4.0 分对话导入

软件勾选后点“一键导入新账号”。请提前登录目标账号。每条对话创建独立聊天，上传各自资料并发送独立提示词，文件每批五个，失败时暂停。大文件受网页额度及格式支持限制。已有导出文件保留。

## 1.4.1 网页 Work 导入

本批统一为网页 Work。每条先选择 Work，核对选中状态，再读取并上传文件。无法确认模式时暂停整批并显示提示。拓展输入框识别以适配不含旧元素 ID 的页面。

## 1.4.2 中文网页

识别顶部“聊天／工作”中文模式切换和中文发送按钮。补充可见文本框识别。

## 1.4.3 连续任务

Work 新页面等待上传控件及菜单加载。完整采集的网页在 ZIP 确认送达并保存断点后自动关闭，再处理下一条。失败和部分采集页面保留。

## 1.4.4 复用处理页

采集与导入共用一个插件创建的处理标签页。采集完成并保存断点后切换下一条链接；导入成功后在同一页进入新聊天。原有聊天保留在账号中。失败时停在当前页。

## 1.4.5 中断与收尾

软件提供“中断上传”。上传和发送前核对任务是否取消，插件轮询后停止页面待上传内容。每批等待回复结束，全部发送后独立发送结束指令。

## 1.4.6 对话改名

网页导入完成后，通过对应侧边栏记录的重命名菜单设置原对话名，核对保存结果。无法确认时在结果里显示原因。
